\subsubsection*{CUDA Programming Guide}
\begin{itemize}
  \item CPU/GPUをホスト/デバイスと呼び分けている
  \item CUDA APIを通してホストメモリからデバイスメモリにデータをコピーすることができる
  \item Graphics Processing Clusters(GPCs)はStreaming Multiprocessors(SMs)の集まり
  \item SMはa local register fileとa unified data cacheと計算を行なう多数の機能ユニットを持つ
  \item 統合データキャッシュは共有メモリとL1キャッシュの実体である
  \begin{itemize}
    \item 統合データキャッシュ -> (共有メモリ, L1キャッシュ)への割り当ては実行時に設定できる
  \end{itemize}
  \item カーネル(GPU上で実行される関数)はスレッドと呼ばれる単位で計算を行う
  \begin{itemize}
    \item スレッドをまとめたものをスレッドブロックという
    \item スレッドブロックをまとめたものをグリッドという
    \begin{itemize}
      \item それぞれのまとめ方は1,2,3次元
      \item 同じグリッド内のブロックの形(次元数)は同じ
    \end{itemize}
    \item こうしてたくさん名称があるのは、処理したいデータ項目とスレッドを対応付けやするため(実装の都合の、仮想的な概念か?)
  \end{itemize}
  \item 同じスレッドブロックに存在するスレッドは同じSMで実行される
  \begin{itemize}
    \item パフォーマンス面で言うと、同じ物理的なメモリを共有することが効く
    \item communicateやsynchronizeが有利
    \item 逆に、異なるスレッドブロックの間のデータのやり取りはオーバーヘッドが大きいことに注意すべし
  \end{itemize}
\end{itemize}
